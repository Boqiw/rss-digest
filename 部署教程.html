一、前置准备

你需要准备以下三样东西：

二、获取 DeepSeek API Key

  1. 打开 DeepSeek 开放平台
    访问 https://platform.deepseek.com，使用手机号注册并登录。
  2. 充值余额
    进入「充值」页面，充值 ¥10 即可（约够用 10 个月）。支持微信/支付宝支付。
  3. 创建 API Key
    进入「API Keys」页面 → 点击「创建 API Key」→ 给个名字（如 rss-digest）→ 复制生成的 Key。
DeepSeek API Key 格式为 sk-xxxxxxxxxxxxxxxxxxxxxxxxxxxxxxxx，请妥善保存，后面要用。

安卓用户

  1. 安装 ntfy 应用

四、创建 GitHub 仓库并上传文件

4.1 需要上传的文件

从你的 rss_monitor/ 目录中，只需要上传以下文件：

.github/workflows/daily-digest.yml # GitHub Actions 工作流配置 .gitignore # Git 忽略规则 README.md # 项目说明文档 requirements.txt # Python 依赖清单 fetch_rss.py # Step 1: 抓取 RSS 文章 ai_filter.py # Step 2: AI 筛选 + 生成摘要 push_ntfy.py # Step 3: 推送到 ntfy pushed_links.json # 去重状态文件（内容为 []） ntfy_topic.txt # ← 不上传！已用环境变量替代 last_run.txt # ← 不上传！首次运行会自动创建 test_*.py / debug_*.py # ← 不上传！测试脚本不需要 __pycache__/ # ← 不上传！Python 缓存 rss_articles.json # ← 不上传！运行时生成 digest.md # ← 不上传！运行时生成
上传前，请确保 pushed_links.json 的内容是 []（空数组），这样 GitHub Actions 首次运行时不会跳过任何文章。如果文件里有之前本地推送过的链接，请清空为 []。

4.2 创建仓库

  1. 新建仓库
    登录 GitHub → 点击右上角 「+」 → 「New repository」

    Repository name: rss-digest（名字随意）
    Description: Daily RSS digest with AI filtering
    Visibility: 选择 Private（私有仓库，保护你的 API Key）
    勾选 「Add a README file」
    不要添加 .gitignore 或 license（我们已有自己的）

    点击 「Create repository」
  2. 上传文件
    在仓库页面点击 「Add file」 → 「Upload files」

    但是 GitHub 网页上传不支持文件夹（.github/workflows/），所以推荐用以下方法：

4.3 推荐上传方式：使用 GitHub Desktop

  1. 下载安装 GitHub Desktop（免费图形化 Git 工具）
  2. 登录你的 GitHub 账号 → Clone 刚才创建的仓库到本地
  3. 将 rss_monitor/ 目录中需要上传的文件（见上方列表）复制到仓库文件夹中

    注意创建文件夹结构：先在仓库根目录创建 .github 文件夹 → 在其中创建 workflows 文件夹 → 将 daily-digest.yml 放入
  4. 回到 GitHub Desktop → 填写 Summary（如 Initial commit）→ 点击 「Commit to main」 → 点击 「Push origin」

4.4 备选上传方式：使用命令行

如果你熟悉命令行，可以在 rss_monitor/ 目录中执行：

# 初始化 Git 仓库

git remote add origin https://github.com/你的用户名/rss-digest.git

# 创建必要的目录结构
# (.github/workflows/ 已存在)

# 确认 pushed_links.json 是空的
echo "[]" > pushed_links.json

# 删除不需要的文件
rm -f ntfy_topic.txt last_run.txt

4.5 确认仓库结构

上传完成后，你的 GitHub 仓库应该长这样：

rss-digest/ ├── .github/ │ └── workflows/ │ └── daily-digest.yml # ⬅ 工作流配置 ├── .gitignore ├── README.md ├── requirements.txt ├── fetch_rss.py ├── ai_filter.py ├── push_ntfy.py └── pushed_links.json # 内容为 []

五、配置 GitHub Secrets

Secrets 是 GitHub 加密存储的环境变量，你的 API Key 和 ntfy Topic 不会暴露在代码中。

  1. 进入 Secrets 设置页面
    在你的仓库页面 → 点击 「Settings」（顶部标签栏）→ 左侧菜单找到 「Secrets and variables」 → 点击 「Actions」
  2. 添加第一个 Secret：DEEPSEEK_API_KEY
    点击 「New repository secret」

    Name: DEEPSEEK_API_KEY
    Secret: 粘贴你的 DeepSeek API Key（sk-xxxx...）

    点击 「Add secret」
  3. 添加第二个 Secret：NTFY_TOPIC
    再次点击 「New repository secret」

    Name: NTFY_TOPIC
    Secret: rss_digest_8a3f7x

    点击 「Add secret」
配置完成后，你会看到两个 Secret 名称列表。Secret 的值一旦保存就无法再次查看，只能更新。如果不确定是否正确，可以重新创建覆盖。

六、手动触发测试

在等待明天 9:00 自动运行之前，我们先手动触发一次测试。

  1. 进入 Actions 页面
    在仓库页面 → 点击顶部 「Actions」 标签
  2. 如果弹出提示
    首次使用 Actions 时，GitHub 会提示你是否信任此 workflow。点击 「I understand my workflows, go ahead and enable them」
  3. 选择 Workflow
    左侧列表中点击 「RSS Digest Daily」
  4. 手动触发
    点击右侧 「Run workflow」 按钮 → 确认分支是 main → 点击绿色的 「Run workflow」
  5. 等待运行
    几秒钟后，下方会出现一条黄色的运行记录。点击进去可以查看实时日志。

    整个流程通常需要 2-5 分钟：
    • 抓取 RSS：~30 秒
    • AI 筛选 + 生成摘要：1-3 分钟（取决于文章数量）
    • 推送到 ntfy：~10 秒
    • 提交状态文件：~5 秒
  6. 检查运行状态
    运行完成后，状态会变成：
    • ✅ 绿色圆圈 = 全部成功，检查手机是否收到推送
    • ❌ 红色叉号 = 有步骤失败，点击进入查看日志排查
    • 🟡 黄色圆圈 = 正在运行，请等待

八、常见问题排查

问题 1：Actions 没有在 9:00 自动运行

GitHub Actions 的 cron 调度可能有 5-30 分钟延迟，这是正常现象。如果延迟超过 1 小时，检查：
  • 仓库 60 天内是否有活动（GitHub 会自动暂停不活跃仓库的 scheduled workflows）
  • cron 表达式是否正确：0 1 * * *（UTC 1:00 = 北京 9:00）

问题 2：Fetch RSS feeds 步骤报错

常见原因和解决方案：

错误信息原因解决方法
ModuleNotFoundError: No module named 'feedparser'依赖未安装检查 requirements.txt 是否已上传
[ERROR] RAND Corporation: 403RAND 有 bot 检测正常现象，代码会跳过该源，不影响其他源
某些源 feed parse errorRSS 源临时不可用正常现象，代码会跳过并继续抓取其他源

问题 3：AI filter 步骤报错

错误信息原因解决方法
未设置 DEEPSEEK_API_KEY 环境变量Secret 未配置或名称错误检查 Secret 名称是否为 DEEPSEEK_API_KEY（区分大小写）
401 Authentication ErrorAPI Key 无效或余额不足检查 Key 是否正确、账户是否有余额
429 Rate LimitAPI 调用频率超限代码已内置重试和 1 秒间隔，如仍超限可稍后重试

问题 4：Push to ntfy 步骤报错

错误信息原因解决方法
未找到 ntfy topicSecret 未配置检查 Secret 名称是否为 NTFY_TOPIC
手机没收到推送Topic 名称不匹配确认手机订阅的 Topic 与 Secret 中的值一致
消息显示为 txt 附件消息超过 4KB代码已内置自动拆分，如仍出现请检查日志

问题 5：Commit state files 步骤报错

此步骤设置了 continue-on-error: true，即使失败也不会中断整体流程。但如果持续失败，状态文件（去重记录）无法持久化，可能导致重复推送。检查：
  • 仓库 Settings → Actions → General → Workflow permissions 是否设置为 「Read and write permissions」
  • 或者确认 workflow YAML 中 permissions: contents: write 已生效

问题 6：如何重新推送所有文章（重置去重）

如果你想重新推送所有文章（比如调试格式），只需：

  1. 在 GitHub 仓库中打开 pushed_links.json
  2. 点击编辑按钮（✏️）
  3. 将内容改为 []
  4. 点击「Commit changes」
  5. 手动触发一次 workflow
